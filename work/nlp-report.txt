ИСТОРИЯ РЕАЛИЗАЦИИ И ПРЕДЫДУЩИХ ПОДМНОЖЕСТВ (не итог полного корпуса)
Нейросетевое извлечение правил: вариант 2025_Б16, учебный прототип
Дата: 04.11.2026. Авторы задания: Виктор Петров, Евгений Смирнов.

Реализация
stroytech.extraction.extract_rules(text, model='qwen2.5-coder:7b', pipeline='filter_first')
вызывает реальный локальный ollama run MODEL --format json --nowordwrap, передавая
prompt через stdin без shell. Перед запуском ollama show проверяет наличие модели:
неустановленная модель отклоняется, автоматического скачивания нет. Тайм-аут стадии
по умолчанию 120 секунд, ввод ограничен 12000 символами, JSON-ответ 64000 символами,
не более 12 правил, 16 условий/следствий в одном правиле. Нет eval, выполнения
ответов модели или подмены сбоя эвристическим «успехом». Ошибки процесса, JSON,
схемы, исходной цитаты и фильтра становятся ExtractionError. Все правила pending.

filter_first: нейросетевой отбор дословных существенных предложений -> нейросетевое
выделение сущностей/намерений, причинных условий и следствий в JSON.
extract_first: нейросетевое выделение полного JSON -> нейросетевой аудит/фильтрация
этого черновика по исходному тексту. Это разные порядки двух реальных стадий.

Правила удовлетворяют общему stroytech.validation.validate_rule, а метаданные
entities, intent, evidence, status дополнительно проверяются в extraction.py.
Источник и ID назначаются приложением, модель не подтверждает свои правила.
Разрешены только согласованные поля и эффекты; fact выводит только equipment_type,
heavy, capacity_ok, access_risk. Категории equipment_type в prompt согласованы с
каталогом. Числа должны быть конечными; отрицательная доплата и небезопасная
структура отклоняются. Противоречия внутри одного правила недопустимы; пересекающиеся
правила сохраняются кандидатами, их совместимость проверяет Repository при ревью.
Противоречие — несовместимые значения факта при совместимых условиях, а не просто
разные тексты рекомендаций. require и reject могут сосуществовать.

Корпус и оценка
В data/extraction_cases.json вручную до прогона размечены 14 синтетических случаев:
скала, нерелевантный текст, отрицание, строгий порог массы, дождь+мягкий грунт,
исключение, доплата, пересечение/противоречие, OR, ЛЭП, отсутствие причинной связи,
нестрогий порог вылета, часы/рубли, грунтовые воды. Gold задает условия и следствия.
Это малый учебный синтетический корпус, не независимый benchmark и не доказательство
производственной точности. Числа/цены — учебные примеры, не инженерные допуски.
Сущности и намерения присутствуют в результатах и требуют экспертной проверки;
автоматическая метрика ниже НЕ измеряет их качество.

Сопоставление — точное равенство множеств правил по спискам conditions/effects,
независимо от порядка элементов и без title/id/source/метаданных. Дубликаты
одинаковых правил считаются один раз. Текст эффекта сравнивается буквально:
синонимы считаются ошибками, логически эквивалентные записи операторов тоже могут
не совпасть. Это консервативная структурная метрика, не семантический судья.
TP — совпавшие правила, FP — лишние, FN — пропущенные; P=TP/(TP+FP),
R=TP/(TP+FN), F1=2PR/(P+R). Micro-метрики суммируют TP/FP/FN по случаям.
Пустой gold и пустой результат дают F1=1; ошибка извлечения всегда отдельно
увеличивает errors, а непустой gold при ошибке увеличивает FN. Поэтому F1 обязательно
рассматривать вместе с errors: сбой на отрицательном примере не ухудшает F1.

Воспроизведение
python3 -m stroytech.experiments --output work/experiments/new-run --limit 4 --timeout 60
Без --limit запускаются все 14 случаев обоими порядками. Каждый case JSON содержит
gold, predicted, error, elapsed_seconds, полные prompt/raw_response/stderr по стадиям.
summary.json содержит модель, installed model ID, версию CLI, prompt version, SHA256
корпуса и суммарные метрики. Нейросетевая генерация может различаться между прогонами.
