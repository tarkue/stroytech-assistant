# СтройТех — учебная экспертная система

Вариант **2025_Б16**, Виктор Петров и Евгений Смирнов. Локальное приложение Streamlit подбирает строительную технику по работам, грунту, погоде и условиям площадки, показывает оценку стоимости и трассу прямого вывода. Цены, грузовые таблицы и дополнительные ограничения учебные; результат требует проверки специалистом и не является разрешением на производство работ.

## Запуск на macOS

Откройте `launch.command` двойным щелчком или выполните:

```sh
./launch.command
```

Скрипт переходит в каталог проекта, создает отдельную `.venv`, устанавливает закрепленные версии из `requirements.txt` и открывает браузер на **http://127.0.0.1:8501**. Первый запуск требует интернет для установки Python-пакетов. Затем подбор работает без сети и без Ollama. Для остановки нажмите **Ctrl+C** в терминале запуска; сервер не публикуется в интернет. Сбор статистики Streamlit отключен.

Нужен Python **3.12–3.14**; проверено на **Python 3.14.4 / macOS arm64**, Streamlit **1.66.1**. Закрепленный NumPy требует Python ≥ 3.12. Другие версии Python/платформы не проверялись. При необходимости выберите интерпретатор: `STROYTECH_PYTHON=python3.14 ./launch.command`.

Ручная установка и запуск:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

Не запускайте `python3 app.py`: Streamlit требует собственный runner. Если порт занят, остановите прежний экземпляр или для ручного запуска добавьте `--server.port=8502`. Локальный адрес и отключенная статистика заданы в `.streamlit/config.toml`.

База `data/app.sqlite3` создается автоматически. Утвержденная БЗ, кандидаты и заказы сохраняются после перезапуска. Для отдельной базы задайте `STROYTECH_DB=/полный/путь/demo.sqlite3`. При обновлении учебного парка существующие экспертные правила и заказы сохраняются. Поля формы и последний расчет сохраняются между действиями текущей браузерной сессии; полное обновление страницы сбрасывает этот черновик, но не SQLite. Экран истории заказов не реализован.

## Демонстрация

1. Во вкладке «Подбор техники» нажмите «Заполнить пример», затем «Подобрать технику».
2. Сравните варианты в таблице и выберите «Подробности варианта». Доступны причины, недостающие данные, состав цены, исходные факты и трасса с промежуточными фактами.
3. Измените грунт и погоду, повторите расчет. После редактирования формы показан последний сохраненный расчет, до следующего нажатия кнопки.
4. Для работ «Подъем» выберите назначение **Груз** либо **Люди и инструмент**. Во втором случае масса — суммарная масса людей и инструмента, а техника — учебная автовышка. Для подъема нужны назначение, масса, вылет и угол; отсутствие значения дает `Нужны данные`.
5. Во вкладке «База знаний» найдите правило, просмотрите источник, условия и последствия; ниже доступен парк и учебные тарифы/грузовые таблицы.
6. Во вкладке «Правила из текста» введите экспертный текст, выберите провайдера, модель и порядок обработки. Запустите извлечение; другие вкладки остаются доступны, статус обновляется автоматически.
7. Проверьте правило в виде «Если / То». Исходный текст и намерение доступны в разделе «Источник и разбор текста», сущности и точные данные — в «Технических данных». Подтвердите либо отклоните кандидата. Неутвержденные кандидаты не участвуют в подборе; дубликаты и конфликты перепроверяются транзакционно при утверждении.

Числа допускают точку и запятую. **Длительность, масса и вылет строго > 0**, угол от **0 до 90°**. Массу, вылет и угол можно оставить пустыми, если они неизвестны или не нужны для выбранной работы. «Неизвестно» не означает безопасные условия.

## Настройка провайдера

По умолчанию извлечение использует локальную Ollama: `qwen2.5-coder:7b`, тайм-аут одного этапа 120 секунд. Скопируйте `config.example.toml` в локальный `config.toml`, чтобы задать несекретные `provider`, `model`, `timeout`. Файл `config.toml` исключён из Git. Переменные окружения имеют приоритет над файлом, явные параметры Python-вызова — над окружением. Модель из файла применяется только к указанному в нём провайдеру.

Для OpenRouter перед запуском экспортируйте `STROYTECH_PROVIDER=openrouter`, `OPENROUTER_MODEL` с выбранным вами точным идентификатором модели и `OPENROUTER_API_KEY` с вашим ключом. Модель автоматически не выбирается. `STROYTECH_TIMEOUT` задаёт тайм-аут одного запроса в секундах, больше 0 и не больше 600. Шаблон имён переменных есть в `.env.example`; `.env` автоматически не читается, переменные нужно экспортировать в окружение запуска.

OpenRouter отправляет экспертный текст внешнему сервису и может тарифицировать запросы выбранной модели. Используется [Chat Completions API](https://openrouter.ai/docs/api_reference/overview) с [Bearer-аутентификацией](https://openrouter.ai/docs/api_reference/authentication); оба этапа конвейера используют одного провайдера. Ключ хранится только в окружении, не вводится в форму и не включается в сообщения об ошибках, трассу или БД. Кандидаты проходят прежнюю валидацию и ручное подтверждение. Реальный платный запрос в рамках проверки реализации не выполнялся; HTTP-контракт и ошибки проверяются локально.

Вкладка «Правила из текста» выбирает начального провайдера из настроек и сохраняет последующий выбор в сессии. Модель берётся из настроек выбранного провайдера; её можно изменить в поле. Для OpenRouter показан только признак наличия ключа и уведомление об отправке исходного текста. До нажатия «Извлечь нейросетью» запросов нет; при неполных настройках показано, что нужно задать, а фоновое задание фиксирует провайдера, модель и тайм-аут на момент запуска. После изменения окружения перезапустите сервер приложения.

Для эксперимента можно явно указать `--provider openrouter`; модель и тайм-аут берутся из тех же настроек либо параметров `--model`/`--timeout`. Для локального варианта используйте `--provider ollama`.

## Нейросетевое извлечение

Для провайдера Ollama нужен локальный CLI `ollama` и **уже установленная** модель `qwen2.5-coder:7b`. Проверьте `ollama list`; поле модели позволяет выбрать другую установленную совместимую модель. Приложение модели не скачивает. Если сервис недоступен на macOS, запустите Ollama (`open -a Ollama`), дождитесь успешного `ollama list` и `ollama show qwen2.5-coder:7b`, затем повторите запрос. Ошибки CLI, тайм-аут, некорректный JSON и схема показываются пользователю, подмены нейросети шаблонами нет.

В поле «Порядок обработки» режим «Сначала убрать лишнее» (`filter_first`) сначала фильтрует исходный текст. Второй режим «Сначала найти правила» (`extract_first`) начинает с извлечения, затем выполняет аудит. Оба исполняют реальные нейросетевые стадии; выбор порядка влияет на ошибки, качество и время. Выводы о качестве ограничены небольшим синтетическим корпусом, полный прогон 14 случаев дал F1 0.421 у `filter_first` и 0.211 у `extract_first` при 3 и 8 ошибках соответственно. Сбой сервиса Ollama в конце смешивает качество и доступность; универсально лучший порядок не установлен. Подробные реальные результаты и ограничения — в [протоколе](docs/protocol.md), [сводке полного прогона](work/experiments/full-v4/summary.json) и [отчёте NLP](work/nlp-report.txt).

Воспроизведение эксперимента:

```sh
.venv/bin/python -m stroytech.experiments --limit 4 --timeout 60 --output work/experiments/new-run
```

Без `--limit` выполняются все 14 случаев обоими порядками. Сохраненные `summary.json` и отдельные ответы содержат фактические ошибки и метрики; unit-тесты с замоканной моделью не являются измерением нейросети.

## Структура проекта

```text
stroytech/
  ui/            # интерфейс Streamlit
  extraction/    # извлечение правил, Ollama и OpenRouter
  storage/       # SQLite и миграции
  validation/    # проверка правил и конфликтов
  core.py        # подбор техники и прямой вывод
  config.py      # конфигурация
  experiments.py # эксперименты
tests/          # ui, extraction, storage, domain
data/           # учебные правила, техника и корпус
docs/           # описание и протокол
scripts/        # проверка HTTP-интеграции
```

## Проверки

```sh
.venv/bin/python -m unittest discover -s tests -v
```

UI проверяется настоящим **Streamlit AppTest**: подбор, сохранение заказа, сохранение состояния между rerun, неизвестные/неверные значения, назначение подъема, предпросмотр и утверждение/отклонение кандидата, фоновая ошибка и сохранение нейросетевого кандидата, настройки и переключение провайдера, отсутствие запросов до нажатия кнопки, фиксация параметров фонового задания. Тесты используют временную SQLite через `STROYTECH_DB`, рабочую базу не изменяют. Для проверки в браузере запустите приложение, пройдите демонстрацию и завершите сервер через Ctrl+C.

См. [архитектуру](docs/architecture.md), [соответствие Б16 и источники](docs/assignment.md), [допущения и протокол](docs/protocol.md). Программные интерфейсы используют обычные словари; отдельного HTTP API и облачной публикации нет.
